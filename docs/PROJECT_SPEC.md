## 背景與目標

Godconverter 目前只能由六位數導向來源作品頁。第一版改做 Chrome Manifest V3 擴充功能，讓使用者輸入六位數後，取得來源作品的可核對中繼資料，並在經驗證的授權中文平台中尋找同一作品的中文版。

成功結果必須落到穩定的官方作品、購買、租閱或閱讀頁。若平台允許下載，使用者依平台正常功能取得檔案；擴充功能本身不代為下載、複製或保存作品內容。

第一版的核心價值是「從來源連結正向發現、正版優先、高精確、可核對」。DLsite 是第一個候選來源，但不是唯一來源，也不得因單一網站可解析就宣稱整體流程可行。

## 名詞

- **來源作品**：由六位數對應的來源頁及其公開中繼資料。
- **授權中文資源**：由著作權人、出版社、作者或取得授權的平台提供的中文作品頁、購買頁、租閱頁或線上閱讀頁。
- **穩定連結**：HTTPS、指向單一作品或系列的 canonical URL，具有可重取的作品識別資料；搜尋結果頁、短網址、轉址廣告及聚合索引不算穩定連結。
- **已確認對應**：至少以原文標題／原題、作者／社團、出版社／品牌、系列或其他明確關聯證據中的兩項核對為同一作品；中文譯名相似本身不足以確認。

## 非目標

- 不搜尋、索引或導向未獲授權的漫畫閱讀、下載或轉載網站。
- 不下載、重製、重新散布或保存漫畫、圖片及其他作品內容。
- 不把搜尋引擎摘要、使用者貼文或聚合站當成最終閱讀／下載資源；它們至多作為尋找官方頁的線索。
- 不翻譯整部漫畫，也不以自行翻譯的名稱冒充官方中文名稱。
- 不繞過驗證碼、Cloudflare、登入、付費、年齡確認、地區限制或其他存取控制。
- 不建立雲端或本機伺服器、帳號系統、資料庫及遙測服務。
- 不承諾每一筆來源作品都有授權中文版。
- 第一版不以 Firefox、Safari、行動裝置或 Chrome Web Store 上架為必要範圍。

## 使用者與主要情境

主要使用者是在 Windows 電腦使用 Chrome 的單一使用者。主要流程如下：

1. 開啟擴充功能側邊面板。
2. 輸入六位數並送出。
3. 擴充功能開啟或切換到來源頁面；如遇人工驗證，提示使用者完成後繼續。
4. 擷取原始標題變體、作者、社團、系列、頁數等可用資料及其證據。
5. 依固定、有上限的策略搜尋已通過 F1 的授權中文來源；日文原名與作者／社團優先，其他標題變體只作補充。
6. 只在身分與中文版本證據充分時顯示已確認的官方中文資源；其餘顯示待確認、未發現中文版、來源未收錄或需要人工處理。
7. 使用者由官方連結進入平台，依該平台提供的線上閱讀、購買、租閱或下載功能使用作品。

## 功能需求

- **REQ-001 六位數輸入**：只接受恰好六位阿拉伯數字；忽略首尾空白，拒絕其他格式並顯示具體原因。
- **REQ-002 持久操作介面**：使用 Chrome 側邊面板承載輸入、進度、錯誤與結果；開啟或切換分頁後介面及工作狀態不得消失。
- **REQ-003 來源導覽**：依輸入數字建立來源網址，在一般 Chrome 分頁開啟；重複輸入相同數字時行為一致。
- **REQ-004 人工接手**：遇到驗證碼、登入、年齡確認、封鎖或非預期頁面時停止自動步驟，提示使用者人工處理後重試。
- **REQ-005 來源資料擷取**：依固定優先序讀取同源 API、內嵌結構化資料、標準中繼資料及畫面 DOM，至少保留日文、英文、顯示用標題、作者／社團、頁數與來源網址；缺少欄位不得臆測。
- **REQ-006 擷取證據**：每個欄位記錄來源類型與必要的欄位路徑或選擇器，以便除錯與人工核對；不得保存頁面全文。
- **REQ-007 授權來源查詢**：只查詢 F1 核准且列於來源登錄表的精確網域。以 URL 編碼的原文標題、作者／社團及受測的標題變體建立查詢；每個 provider 的查詢次數須有上限且可停止。
- **REQ-008 中文資源候選擷取**：取得 provider、商品／作品代號、中文標題、原題、作者／社團、出版社／品牌、語言或版本提示、canonical URL、可用方式（閱讀、購買、租閱、下載）及欄位證據；不得下載作品內容。
- **REQ-009 確定性配對**：以固定規則完成 Unicode NFKC、大小寫、標點、括號標籤、常見版本字樣與空白正規化，再依標題、作者／社團及明確版本關聯計分；不得呼叫 AI 或遠端判定服務。
- **REQ-010 信心與結果分級**：結果至少區分「已確認官方中文資源」「待確認候選」「找到原作但未發現中文版」「授權來源未收錄」「需要人工處理」。只有分數、證據數與第一、第二名差距同時達門檻時才自動確認。
- **REQ-011 可核對結果**：顯示來源資料、候選 provider、各欄位吻合情形、身分證據、中文版本證據、總分、信心等級及兩側原始連結。
- **REQ-012 本機狀態**：以 `chrome.storage.local` 保存必要的工作狀態、最近查詢與使用者設定；不保存 Cookie、密碼、頁面全文或作品內容，並提供清除紀錄功能。
- **REQ-013 正向批次測試資料**：初始盲測集合包含 `611888`、`299075`、`668297`、`637940`、`678718`、`460733`、`405606`、`604456`、`337285`、`609219`、`672835`、`363218`，再補到至少 20 個事先固定的唯一號碼。重複輸入 `460733` 與 `363218` 用於一致性測試，不計入唯一樣本數。不得因已知某平台有商品而挑選主要盲測樣本。
- **REQ-014 錯誤處理**：區分格式錯誤、作品不存在、來源無法存取、需要人工處理、擷取器失效、provider 無結果、未發現中文版本、候選歧義及內部錯誤；每種狀態提供下一步。
- **REQ-015 診斷匯出**：允許使用者複製不含 Cookie、頁面全文及作品內容的診斷摘要，包括版本、輸入號碼、階段、provider、錯誤代碼、擷取策略及候選分數。
- **REQ-016 補驗追蹤**：Computer Use、外部網站狀態或人工步驟使代理無法執行的實機驗收，必須逐項記錄操作步驟、預期結果、受阻原因與狀態，集中於補驗清單；不得把未執行項目寫成通過。
- **REQ-017 授權中文資源可行性閘門**：正式實作多來源查詢與配對前，必須從事先固定的來源號碼正向搜尋，驗證 provider 搜尋能力、canonical URL、中文版證據、原作關聯證據及人工接手。只測試預先知道的商品頁或只證明 DOM 可解析，均不足以放行 A3 至 A6。
- **REQ-018 授權來源登錄表**：每個 provider 必須記錄營運者、授權／正版聲明、用途、精確網域、查詢入口、canonical URL 規則、可用方式、必要權限、實測日期與狀態。未通過者不得進入正式 manifest 或結果 UI。

## 品質需求

- **QREQ-001 精確度**：所有能正常顯示的來源與 provider 案例，擷取值須與頁面或同源結構化資料對得上；不可把翻譯或猜測寫成原始標題或官方中文名稱。
- **QREQ-002 高信心精確率**：經人工建立真值的跨來源案例中，高信心自動判定精確率至少 95%；樣本不足 20 筆時不得宣稱達到統計門檻，且觀察期間不得有已知錯配。
- **QREQ-003 正向發現率**：對人工確認確實存在授權中文版的案例，系統須找回至少 80%；正例少於 5 筆時須擴充盲測集合或回報證據不足，不得放行。
- **QREQ-004 涵蓋率透明**：分開報告來源作品總數、授權原作存在數、授權中文版存在數、成功找回數與高信心確認數；不得以精確率取代涵蓋率。
- **QREQ-005 保守失敗**：無法確認同一作品時，優先回報待確認或未找到，不得用降低門檻換取較高命中數。
- **QREQ-006 可重現性**：相同輸入、相同頁面資料與相同設定必須得到相同正規化結果、分數與排序。
- **QREQ-007 效能**：排除網站載入與人工操作時間，單次本機解析及排序在驗收裝置上應於 500 毫秒內完成。
- **QREQ-008 可維護性**：來源與每個 provider 的擷取規則各自封裝成 adapter；純資料正規化及計分不得依賴 DOM，固定資料測試可離線執行。
- **QREQ-009 可觀察性**：使用者能辨識目前處於來源載入、人工接手、資料擷取、provider 搜尋、候選評分或完成狀態。
- **QREQ-010 無障礙基本要求**：主要操作可用鍵盤完成，表單有 label，狀態訊息可被輔助科技讀取，不能只靠顏色區分信心。

## 相容性與既有功能

- **COMP-001**：第一版以 Windows 上的 Chrome 為主要環境，最低版本暫定 Chrome 114，實機驗收使用本機 Chrome 152。
- **COMP-002**：採 Manifest V3，只執行擴充功能封裝內的程式碼，不使用遠端載入的 JavaScript。
- **COMP-003**：保留「由六位數開啟來源作品」的既有能力，但不要求沿用 Flutter 程式碼或介面。
- **COMP-004**：Edge 相容性可在 Chrome 版穩定後評估，第一版不為 Edge 差異增加阻擋條件。

## 資料、安全與隱私

- **SEC-001 最小權限**：只申請 `sidePanel`、`storage`、必要的 Chrome API 及已通過 F1 的精確來源／provider 網域；不得使用 `<all_urls>`。
- **SEC-002 工作階段隔離**：擴充功能使用目前 Chrome 分頁的正常工作階段，不讀取或持久化 Cookie、Authorization header、密碼或驗證碼。
- **SEC-003 不可信內容**：來自網頁的文字一律視為不可信資料；插入 UI 時使用 `textContent` 或等效安全方式，不用未清理的 `innerHTML`。
- **SEC-004 訊息驗證**：所有跨 side panel、service worker、content script 與頁面主世界的訊息必須驗證來源、tab、schema、長度與允許欄位。
- **SEC-005 外部導覽**：只允許建構來源登錄表中核准網域的 HTTPS 網址，查詢內容須正確編碼；任何網頁資料不得直接控制任意 URL。
- **SEC-006 資料最小化**：本機紀錄設數量上限，能由使用者清除；診斷資料不得含敏感工作階段資訊、完整頁面內容或作品內容。

## 成功條件

1. 擴充功能能以未封裝形式載入本機 Chrome 152，無 Manifest 錯誤。
2. 從六位數輸入、來源資料擷取、授權中文來源搜尋，到已確認資源或明確未找到狀態的完整流程可在側邊面板完成，且不需伺服器或 AI。
3. 成功結果直接提供已核准 provider 的 canonical 作品頁，並標示該平台實際提供的線上閱讀、購買、租閱或下載方式。
4. REQ-013 的盲測集合完成正向驗證，分開報告中文版本存在率、發現率、精確率與 abstention rate，並符合 QREQ-002、QREQ-003。
5. 每個自動確認結果都有至少兩項身分證據及明確中文版本證據；無證據時不得輸出為官方中文資源。
6. 權限、儲存與訊息通道通過檢查，不保存禁止資料、不導向未授權資源，也不繞過網站保護。
7. 離線單元測試、固定頁面測試、整合測試及實機驗收均有可追溯紀錄；所有 blocking 驗收通過前不得宣稱專案最終完成。

## 限制與已知未知事項

- 來源網站與授權平台的 DOM、API、反自動化策略、網域及商品供應會改變；必須記錄實測日期並以 adapter 隔離。
- 來源作品可能只有翻譯後標題、羅馬字作者或不完整社團資料；這會直接降低跨平台發現率。
- 授權平台之間沒有共同作品 ID。中文譯名可能與原題無字面關係，因此只有標題相似度不足以確認身分。
- 某些來源作品從未正式發行、未授權中文版本、已下架或受地區限制；系統應如實回報，不得改導向未授權副本。
- 搜尋引擎可作為發現官方 canonical URL 的備援入口，但搜尋摘要不能作為最終身分或授權證據。
- Chrome content script 執行於隔離環境；若同源資料只能由頁面主世界取得，必須使用封裝內腳本及嚴格訊息 schema，不得注入遠端程式碼。
- 目前工作區不是 Git repository；不得自行初始化 Git。
