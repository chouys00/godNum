# 查詢速度與速率控制（v0.4.1）

2026-09-13 核對 [來源官方 OpenAPI](https://nhentai.net/api/v2/openapi.json)，版本 `2.0.0+483414f`：匿名 `GET /api/v2/galleries/{gallery_id}` 為每 IP 每分鐘 20 次，`GET /api/v2/search` 為每 IP 每分鐘 10 次。舊文件僅記載 20 次並不完整；不能將它套用到搜尋。

## 實作

- 使用專屬 runtime port 逐筆傳回 metadata 與完整結果；先顯示原始標題、作者與來源頁，中文版本尚未完成時明確顯示查詢中。補上版本時保留原欄位節點與鍵盤焦點。內部 20 秒心跳只維持 Chrome 114 背景連線，不呼叫網站。
- 同一批相同搜尋 URL 的成功候選在記憶體重用，仍針對每筆來源重新核對作者、頁數與標題；失敗不重用。批次最多十筆，最多保留每個搜尋前 25 筆配對所需 metadata，不保存頁面或作品內容。
- 所有面板與相容單筆訊息共用序列佇列：全 API 發送至少間隔 3,100ms，搜尋另需間隔 6,100ms，分別限制為任意 60 秒最多 20／10 次。延遲的計時器不補發突波；請求仍維持 20 秒逾時。
- 429／503 阻擋後續兩種端點，支援 Retry-After 秒數與 HTTP 日期；至少冷卻 61 秒。當筆回報失敗，不自動重試；其餘筆繼續依冷卻排程。重新導向視為錯誤，避免未經限流的第二個 HTTP 請求。
- `chrome.storage.local.apiPacingV1` 僅有 `globalAt`、`searchAt` 兩個毫秒時間值。發送前先保存保守 61 秒保留額度，完成後保存正常節奏或更長的冷卻；背景中斷也不會直接重設為無限制。讀寫失敗或資料損壞則停止發送。新增必要的 `storage` 權限，不新增網域、依賴、伺服器或資料庫。
- 關閉面板中止正在進行的 fetch，佇列中尚未發送的查詢會取消，不再消耗額度。再次打開沒有先前輸入或結果，限流時間仍有效。

## 離線量測

固定虛擬時鐘、每次 API 回應 100ms、無先前額度使用，十筆不同標題：

| 指標 | 舊流程 | v0.4.1 |
|---|---:|---:|
| 第一筆 metadata 可供顯示 | 59,000ms（等整批） | 100ms |
| 第一筆完整結果可供顯示 | 59,000ms（等整批） | 3,200ms |
| 十筆全部完成 | 59,000ms | 59,000ms |
| 三筆相同搜尋的 API 次數 | 6 | 4 |

這是可重現的排程與傳訊測試，不是 Chrome 實際繪製或網路延遲量測；不存在冷卻時首筆 metadata 只需等待一次來源 API。不同標題的整批仍受額度限制，不宣稱全面縮短一分鐘總工期。

`node test/run-quality-gate.mjs` 包含端點滑動窗口、90 個混合並發排程、慢回應／計時器延遲、重啟、429 秒數／日期、無效標頭、取消、儲存失敗、來源驗證、重複批次忽略、串流 UI 與斷線清理；51 個 JavaScript 檔案及七種違規 fixture 通過。

## 待實機補驗

1. 從舊版升級時先等待距離最後一次 API 操作至少一分鐘，再重新載入 v0.4.1，確認 `storage` 權限可用。
2. 分別查詢單筆與十筆混合案例，記錄點擊、首筆 metadata、首筆中文版本與整批完成時間，核對版本等待狀態與錯誤隔離。
3. 以背景網路面板確認相鄰 API 至少 3.1 秒，搜尋至少 6.1 秒；兩個面板共用節奏，不為了驗收刻意製造 429。
4. 查詢中關閉面板，確認後續請求取消；重新開啟沒有查詢內容。停止／重啟背景後，確認先前限流時間仍有效；慢網路與長冷卻期間應保持連線或明確回報中斷。
5. 核對本版儲存鍵只包含兩個數值，沒有號碼、標題、URL 或候選。A6 仍為 pending，完成前不得標記專案 accepted。

限制：來源按 IP 計額度，同 IP 的其他程式、分頁或裝置不受本擴充功能控制，仍可能造成 429；本版只保證本擴充功能自身排程，並遵循收到的冷卻訊號。來源將來變更額度時須重新核對官方規格。
