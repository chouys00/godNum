# 決策紀錄

## DEC-001：第一版採 Chrome Manifest V3

- 日期：2026-09-10
- 狀態：accepted
- 背景：主要在 Windows 電腦使用，現有環境已有 Chrome 152，但沒有 Flutter、Dart 或 Visual Studio。
- 考慮方案：Chrome 擴充功能、Flutter Windows、.NET WebView2、Electron、Tauri。
- 決定：第一版採 Chrome Manifest V3 擴充功能。
- 理由：不需新增開發環境即可從原生 HTML、CSS、JavaScript 起步，能在正常瀏覽器分頁沿用使用者工作階段，且不需伺服器。
- 影響：第一版以 Chrome APIs 與未封裝載入為準，跨平台桌面封裝延後。
- 取代關係：無。

## DEC-002：使用 Chrome 側邊面板承載主要介面

- 日期：2026-09-10
- 狀態：accepted
- 背景：傳統 action popup 在切換或開啟分頁時會關閉，不利於顯示長流程進度與人工接手狀態。
- 考慮方案：action popup、獨立擴充功能分頁、Chrome side panel。
- 決定：以 side panel 作第一版主要介面，最低 Chrome 版本暫定 114。
- 理由：介面可在網站分頁切換時持續存在，適合輸入、進度、候選比較與重試。
- 影響：manifest 需申請 sidePanel 權限；Edge 相容性留待後續評估。
- 取代關係：無。

## DEC-003：配對不使用 AI，採保守的固定評分

- 日期：2026-09-10
- 狀態：accepted
- 背景：使用者要求流程不依賴 AI，並重視準確率。
- 考慮方案：AI 語意比對、遠端搜尋服務、本機固定規則。
- 決定：採本機、可重現的字串正規化與加權評分，信心不足時不自動判定。
- 理由：能離線測試、解釋判定原因並避免模型或服務變動造成結果漂移。
- 影響：需建立人工真值集與門檻校準報告；不同譯名的涵蓋率可能低於 AI 方法。
- 取代關係：無。

## DEC-004：不建立伺服器，也不繞過網站保護

- 日期：2026-09-10
- 狀態：accepted
- 背景：使用者希望個人電腦直接使用，並詢問是否需要伺服器。
- 考慮方案：雲端代理、本機代理、瀏覽器分頁與 content script。
- 決定：第一版只使用擴充功能、一般網站分頁與 Chrome 本機儲存；人工完成網站要求的驗證。
- 理由：降低部署與隱私成本，也避免擴充功能處理敏感工作階段資料。
- 影響：網站阻擋時流程會等待人工操作，不能保證全自動。
- 取代關係：無。

## DEC-005：合法商店搜尋限於 DLsite

- 日期：2026-09-10
- 狀態：accepted
- 背景：使用者指定以 DLsite 設計流程，目的是從來源標題找可信度較高的作品頁面或語言版本。
- 考慮方案：DLsite、其他合法商店、多來源聚合、未獲授權下載站。
- 決定：第一版只整合 DLsite；其他合法商店日後另立需求評估。
- 理由：先縮小網域權限及擷取器範圍，才能建立可核對的準確率基線。
- 影響：沒有 DLsite 收錄的作品會回報未找到，不能視為流程錯誤。
- 取代關係：無。

## DEC-006：第一版完成後清除不必要的留存設定

- 日期：2026-09-10
- 狀態：accepted
- 背景：使用者要求計畫完成後移除非必要的留存設定。
- 決定：保留使用者主動選擇保存且仍為功能所需的最小本機狀態；移除開發、驗收與暫時性設定檔、測試設定檔與不再需要的紀錄。擴充功能必須維持清除本機紀錄功能。
- 影響：A5 的安裝、清除與移除說明及 A6 最終驗收需確認沒有遺留測試設定檔、Cookie、瀏覽資料、頁面全文或作品內容。
- 取代關係：無。

## DEC-007：可自動驗證功能先完成，實機操作集中補驗

- 日期：2026-09-11
- 狀態：accepted
- 背景：Computer Use 會阻擋來源網站、瀏覽器內部頁面與部分外部網站操作，無法代替使用者完成全部實機驗收。使用者要求先串接並測試 A1 至 A6 可由代理完成的功能，再共同補驗。
- 考慮方案：維持每階段實機 blocking 驗收、把未執行項目視為 waived、將實機驗收改為可追蹤補驗並在 A6 最終阻擋。
- 決定：A2 至 A5 的外部或實機核對改為 non-blocking，逐項列入 `SUPPLEMENTAL_VALIDATION.md`。各階段仍須完成自動測試與必要獨立審查。A6 完成自動工作後維持 `implementation_complete` 與 `CONCERNS`，直到使用者完成 ACC-A6-001。
- 理由：避免工具限制阻斷程式實作，同時保留所有未驗證事實，不把未執行驗收寫成通過。
- 影響：階段技術 gate 可依自動證據前進；真實網站正確性、Chrome 載入與人工流程仍須補驗。未經實機補驗不得發布最終 accepted 結論。
- 取代關係：取代 A2 至 A5 原先「實機驗收逐階段 blocking」的安排，不改寫 A1 已通過的歷史，也不取消 A6 最終 blocking 驗收。

## DEC-008：DLsite 核心可行性須在正式實作前通過

- 日期：2026-09-11
- 狀態：accepted
- 背景：A3 原型開始後才發現 DLsite 搜尋頁、商品頁語言訊號與原作關聯均缺乏實站證據；若這些欄位不存在，後續配對與完整流程沒有可行基礎。
- 考慮方案：繼續完成離線實作後集中補驗、只做人工觀察、先建立可丟棄的最小 Probe 並設 blocking 閘門。
- 決定：在 A2 與 A3 之間新增 F1。F1 只驗證 DLsite 搜尋、商品頁繁中訊號、原作關聯證據及人工接手，ACC-F1-001 通過前不得接續 A3 至 A6。
- 理由：用最低實作成本淘汰不可行的資料假設，避免以 fixture 自證尚未存在的網站欄位。
- 影響：原 A3 已寫的候選原型保留但凍結，不得視為 F1 通過證據；後續範圍依 F1 實測結果決定。
- 取代關係：取代 DEC-007 中「A3 的外部網站核對可延後且不阻擋後續實作」部分；DEC-007 其餘內容維持有效。

## DEC-009：實站等待期間只執行網站無關基礎

- 日期：2026-09-11
- 狀態：accepted
- 背景：使用者目前無法操作 Chrome，但 A3 至 A6 含有可由代理離線驗證、且不依賴 DLsite 真實欄位的共用工作。
- 考慮方案：完全停止、直接執行 A3 至 A6、把網站無關工作抽成獨立階段。
- 決定：新增 B1「純文字與評估核心」、B2「本機可靠性與安全基礎」、B3「自動品質閘門」，依序完成後回到 F1 blocking 實站驗收。
- 理由：可以利用等待時間，同時避免把未驗證的 DLsite DOM、語言欄位、權重與門檻寫死。
- 影響：A4 至 A6 日後只需整合及驗證剩餘的網站相依功能；B1 至 B3 的通過不代表 DLsite 可行。
- 取代關係：補充 DEC-008，不取代 F1 blocking 閘門。

## DEC-010：產品目標縮小為具來源的中文名稱

- 日期：2026-09-12
- 狀態：accepted
- 背景：使用者不再要求 DLsite 或閱讀／購買資源，只要由六位號碼取得同一作品的中文名稱與可用作者，並明確取消查詢保存。
- 決定：正式目標改為首次名稱查證；接受正式譯名或有來源的通行別名，不接受自行翻譯冒充既有名稱。方法不受舊架構限制，但額外費用必須為零，且優先不依賴 Codex。
- 影響：DLsite F1 與 A3 至 A5 舊方向 superseded；A1、A2、B1 至 B3 可重用。新實作必須移除查詢歷史與持久化候選。
- 取代關係：取代 DEC-005、DEC-006 中要求保留必要查詢狀態的部分，以及 DEC-008 的現行阻擋地位；歷史測試結果不刪除。

## DEC-011：獨立零費用方案未通過，停止完整實作

- 日期：2026-09-12
- 狀態：accepted
- 背景：同站 v2 搜尋能找到部分中文翻譯版本，但公開 metadata 常只有羅馬字與翻譯標記，沒有中文名稱。一般免費書目 API 也缺乏目標類型涵蓋。
- 決定：以凍結規則完成 10 筆留置測試；結果 1/10、0 次已知誤配，未達 8/10 門檻。V3 判定 FAIL，在使用者核准替代契約前不開始完整實作，也不自行切換 Codex。
- 理由：缺口在資料來源，不在 UI 或配對程式；繼續開發無法滿足「第一次穩定給出具來源中文名稱」。
- 影響：下一階段為 C1 使用者決策。可討論自動直譯、Codex、人工確認或接受低覆蓋率。
- 取代關係：補充 DEC-010。

## DEC-012：改採中文版本連結與本機機器直譯

- 日期：2026-09-12
- 狀態：accepted
- 背景：具來源中文名稱的留置覆蓋不足，但 nhentai v2 能找到部分同作中文翻譯 gallery。使用者不再強求正式或既有中文名稱。
- 決定：輸出通過同作核對的中文版本 nhentai 連結；無論是否找到版本，都以 Chrome 內建 Translator API 將來源名稱在本機翻成繁體中文。作者／署名保持原文。機器直譯清楚標示，不冒充正式譯名。
- 風險授權：使用者已知情並明確授權中文版本連結可能直接導向成人作品頁。
- 費用與隱私：語言包由 Chrome 首次免費下載，翻譯在裝置上執行；不使用 Codex 或付費 API，不保存查詢。
- 影響：最低 Chrome 提高到 138；Translator 在 side panel 執行。manifest 移除 DLsite、tabs、storage 與 content scripts。
- 取代關係：取代 DEC-011 的停止狀態；保留其舊契約 NO-GO 證據。

## DEC-013：以受限批次取代單筆互動

- 日期：2026-09-12
- 狀態：accepted
- 背景：使用者要求一次輸入多組號碼並收取整批資訊。
- 決定：側邊面板一次接受 1 至 10 組唯一的六位數號碼，以空白或逗號分隔。每組的來源 metadata、中文版本連結與本機翻譯獨立呈現；單筆失敗不影響其他組。背景程式在記憶體中依序排程 API 請求，以符合匿名速率限制。
- 影響：完整 10 筆可能需要約一分鐘；不新增權限、持久化、伺服器或 AI，且批次資料於關閉側邊面板後消失。
- 取代關係：補充 DEC-012；單筆 runtime 訊息保留為相容內部介面，但側邊面板改用批次訊息。

## DEC-014：作品欄位交由 Chrome 預設搜尋引擎查詢

- 日期：2026-09-13
- 狀態：accepted
- 背景：使用者要求原始標題、作者／署名與社團在有資料時可點擊搜尋，且外觀與來源頁超連結一致。
- 決定：非空欄位使用原生超連結外觀；點擊時呼叫 `chrome.search.query`，以該欄位完整顯示字串在新分頁執行 Chrome 預設搜尋。缺值仍顯示不可點擊的「未提供」。
- 影響：manifest 新增 `search` 權限；不固定 Google 或其他搜尋供應商、不新增 host permission、不保存搜尋字串。
- 取代關係：補充 DEC-012 與 DEC-013。

## DEC-015：移除本機離線翻譯

- 日期：2026-09-13
- 狀態：accepted
- 背景：使用者要求刪除本機離線翻譯功能及所有相關程式、測試、依賴與資源。
- 決定：移除 Chrome Translator wrapper、UI 翻譯與重試流程、語言包進度、來源 record 的翻譯標題／語言欄位及專用測試。原始標題改用配對時已存在的 `searchTitle` 顯示與搜尋。
- 影響：不再建立或下載語言包；最低 Chrome 版本由 138 恢復為 side panel 所需的 114。批次 metadata、中文版本連結與欄位搜尋不變。
- 取代關係：取代 DEC-012 中所有本機翻譯決定；中文版本連結、作者原文與不保存部分仍有效。
