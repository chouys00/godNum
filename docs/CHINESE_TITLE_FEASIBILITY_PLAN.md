# 中文名稱查證：獨立、零額外費用方案

- 日期：2026-09-12
- 文件狀態：已執行；獨立零費用方案未通過 V3 閘門。
- 本文件取代 `CHINESE_TITLE_PLAN_DRAFT.md` 的提案內容；正式階段控制仍以 `STAGE_STATE.yaml` 為準。
- 後續執行者：Terra。開發使用 Codex，優先方案在執行查詢時不依賴 Codex。

## 已確認目標

使用者輸入六位號碼，工具取得 nhentai 作品頁的非露骨書目中繼資料，從外部名稱資料找出同一作品的中文名稱與可用作者名稱。正式出版譯名及有來源可核對的通行中文別名均可。使用者自行將名稱用於其他搜尋。

來源通常沒有中文資訊，因此只解析原頁不能視為完成。中文名稱必須在可查證的外部書目證據中出現，不能以模型或機器自行翻譯代替。範圍限名稱與作品身分核對，不搜尋或導向色情作品閱讀、下載來源，不讀取作品圖片、封面或內文。

## 硬限制

1. 首次處理即完成查詢與核對；可以在同一次處理內發出多個有界請求，但不可依靠過往人工對照表或重複查詢累積命中率。
2. 工具不保存號碼、標題、作者、候選、證據或查詢歷史。僅在當次記憶體使用，結束或關閉後移除；不使用持久化快取、瀏覽器 storage、檔案日誌或遙測保存查詢資料。
3. 額外服務費用為零：排除付費 API、主機、代理、付費試用及會自動轉付費的服務。免費服務額度耗盡時停止或切換已核准免費來源。
4. 優先不依賴 Codex 或雲端模型推論。免費外部網站／API 可以評估；本機模型只在固定規則不足且硬體可支援時評估，不先下載或安裝。
5. 不受既有 Chrome 架構限制。選型依實際資料存取、穩定性及部署成本決定；不為沿用程式而犧牲需求。
6. 不繞過驗證碼、登入、網站存取限制或其他保護。人工接手頻率必須列入結果，不能算全自動成功。
7. 等待時間尚未設定。實驗必須有請求與時間上限；初步建議每筆最多 12 次外部請求、180 秒，包含重試，且使用者可取消。這是實驗預算，不是已驗證效能或使用者指定上限。

「不保存」是工具行為。瀏覽器歷史、作業系統與第三方服務可能留存資料；須實測與揭露，不能宣稱外部服務零留存。開發文件只記錄規則、去識別化合成 fixture、彙總結果與缺口，不建立真實作品對照資料庫。

## 第一階段：來源與方法驗證（最重要的阻擋閘門）

### V1：找出可供獨立程式使用的免費名稱來源

評估一般出版／書目 API、包含原文與中文名稱對照的公開書目頁，以及明確允許自動查詢的免費搜尋介面。不得因人能在瀏覽器搜尋，就推定有免費且可靠的程式查詢方式。

每個候選來源必須檢查：

- 費用、金鑰／註冊要求、免費上限與是否有超額收費。
- 官方文件或服務說明所支持的自動使用方式；不把未記載的私有介面視為穩定 API。
- 可用查詢欄位、中文別名／原題／作者等實際回傳欄位與證據網址。
- 書目涵蓋範圍，尤其單篇、同人作品與合集是否能識別；一般書籍 API 能查書不等於覆蓋目標類型。
- 本機直接呼叫、瀏覽器限制、速率限制、阻擋與錯誤行為。
- 名稱資訊是否能在不取得作品內容、閱讀／下載入口的情況下核對。

產出為來源能力矩陣，狀態使用「待查證／已驗證／不適用／受阻」。先前討論提及的服務均不自動視為已核准來源；搜尋 API 的付費方案不得納入零費用主路徑。

### V2：比較首次名稱查證方法

在不保存真實查詢資料的前提下，逐筆以記憶體處理輸入和核對證據。人工只為實驗建立真值與評分，不能成為產品每次必經步驟，也不能把人工找出的答案傳回查詢流程當線索。

方法 A：原始標題及清理後標題 → 外部書目候選 → 原題與作者核對。

方法 B：方法 A 失敗後，使用有證據的作者別名、系列、卷次或收錄關係擴充查詢；作者相同或系列相同本身不能確認作品。

方法 C：僅當 A／B 已取得足夠證據但文字關係解析失敗，才比較本機模型輔助。模型只能解讀當次取得的資料，不能從記憶補答案；輸出名称須能回指證據中的文字。

先用至少 10 筆未按成功結果挑選的來源中繼資料做探索。探索後凍結方法，再用至少 10 筆新樣本做首次查詢驗證。樣本只涉及書目文字；無法安全取得實站資料時列受阻，不以合成測試冒充。合成 fixture 用於程式邊界測試，不用於證明網站收錄率。

每次記錄彙總計數：全部輸入、來源可讀、正確取得名稱、錯認、證據不足、存取受阻、人工接手、請求數與耗時。不保存真實名稱／號碼對照；因此不能聲稱可永久重播原始實站批次，重現性另用去識別化 fixture 驗證。

### V3：判斷是否值得實作

- 主要指標：首次正確取得率＝正確取得中文名稱的輸入數／全部輸入數。不可把無結果與受阻當成功，也不可排除難例美化分母。
- 確認精確率＝正確確認數／全部確認數；無確認時為 N/A。小樣本要求零已知錯认，並報分子分母，不宣稱統計保證。
- 已知存在名稱的找回率另報；真值未知者單獨列出，查不到不等於名稱不存在。
- 建議候選放行條件：保留樣本首次正確取得率至少 80%、零已知錯認、無付費請求、查詢時不依賴 Codex。80% 是待使用者審閱的工程門檻，不是既有保證。
- 未達標時指出原因：外部名稱資料缺少、免費來源存取不可靠、原作身分資料不足或核對能力不足。只有核對能力不足且已有證據時，才有理由討論 Codex 輔助；不自動切換。
- 若資料來源尚未證實，停在方法驗證，不直接開發完整 UI 或宣稱整套流程可行。

## 第二階段：核准方法後實作

1. 同步正式規格、Roadmap、決策、交接、驗收與 `STAGE_STATE.yaml`。保留原階段歷史，標註被新範圍取代的需求，不改寫歷史 FAIL／pending 為通過。保留 A6 最終人工驗收。
2. 依 V1 實測選擇純瀏覽器擴充功能或本機程式；若必須使用付費伺服器才能成立，方案不符合限制。任何免費金鑰與使用設定不得硬編碼，保存設定與保存查詢資料須分清楚。
3. 分離來源解析、外部書目查詢、候選核對與輸出模組。查詢有去重、超時、有限重試、取消與速率控制。外部文字視為資料，不執行其指令或腳本。
4. 名稱確認需直接原題對照或足以確認身分的多項證據；多個網站轉載同一資料不當成多份獨立證據。單篇與合集分開，合集名稱只能標成收錄關係，不能冒充篇名。
5. 當次輸出：中文名稱／其他可信別名、作者（未知則明示）、名稱類型、非內容導向的書目證據及狀態。多個相容別名可以並列；身分衝突回報待確認。
6. 移除查詢流程的 `chrome.storage.local` 保存、歷史列表及自動診斷留存；只保留當次記憶體狀態。若關閉即丟失是設計行為，就不再要求跨關閉恢復。

## 測試與交付

- 離線：標題正規化、作者別名證據、純漢字語言歧義、卷次、單篇／合集、來源矛盾、空結果、惡意文字、超長欄位及相同輸入可重現性。
- 整合：取消、超時、速率限制、免費額度耗盡、來源改版、人工接手、不同查詢不串資料。
- 無保存：檢查 browser storage、檔案、日誌、暫存與遙測路徑；敏感真實查詢不納入測試輸出或文件。
- 零費用與獨立執行：檢查所有外部呼叫與設定，移除 Codex／模型 API 憑證後完整跑一次；成功必須來自工具本身，不能由開發代理代查答案。
- 若仍用現有 JS 專案，按修改範圍更新品質閘門並執行 `npm run quality`；若改架構則記錄對應測試入口，不能用舊测试通過代表新工具通過。
- A6 由使用者核對實際輸出、第一次查詢表現與不保存行為。受工具限制的實站操作列補驗，完成前不得最終 accepted。
